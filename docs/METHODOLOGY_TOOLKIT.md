# Методология evidence-gates как переиспользуемый инструмент

Ядро проекта Bering, не привязанное к Магадану: подходит для любого инвестиционного исследования, где нельзя путать «нет данных» с «нулём» и «публикацию» с «контрактом».

## 1. Правила (AGENTS.md)

14 правил: доказанный груз требует документа; missing = null; не смешивать единицы, периметры и периоды; дополнительность считается после вычета каннибализации; fail-closed по умолчанию.

## 2. Шкала доверия к источнику

`публикация/пресс-релиз < тариф/прейскурант < твёрдая котировка < подписанный контракт < исполненная перевозка (B/L) < оплаченный счёт < банковская сверка`. Каждый переход требует отдельного документа с SHA-256 и независимым проверяющим.

## 3. Паттерн fail-closed gate (см. `scripts/commercial_gate.py`)

- Вход = JSON-кейс + реестр evidence-записей `{id: {sha256, status: VERIFIED, reviewed_by, reviewed_on}}`.
- Любой неполный/неверифицированный вход → `HOLD` с явными списками `errors`/`missing`.
- Результат никогда не содержит «одобрено»: `bankable_revenue_approved` всегда `false`, деньги — только `Decimal`, единицы зафиксированы.
- Решение о переходе HOLD → REVIEW → PASS принимает человек/комитет, не скрипт.

## 4. Минимальный чек-лист для нового проекта

1. Скопировать `AGENTS.md`, адаптировать периметры и единицы.
2. Определить пилоты/гипотезы и список обязательных категорий документов.
3. Реестр evidence с SHA-256 первичных байтов; Git = единственный источник правды.
4. CI: единый workflow, запускающий валидаторы на каждом PR; GREEN обязателен для merge.
5. Дашборд статуса (см. `docs/EVIDENCE_DASHBOARD.md`) — одна страница правды.

## 5. Анти-паттерны, которые инструмент ловит

- Подмена missing нулём; суммирование разных единиц/периметров; двойной счёт одного контейнера в двух пилотах; принятие плановой мощности за фактический груз; «зелёный» CI без исполненных шагов; локальный PASS, выданный за независимую приёмку.
