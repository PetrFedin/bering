# How to develop the Bering research further

## Every new version
1. Declare the specific engineering/commercial/finance question, decision and alternatives.
2. Link primary sources with observed date, access date, geography, origin, unit, definition, tax basis and caveats.
3. Save source originals (with rights to redistribute) separately from annotated extracts and reviewer notes.
4. Update numeric observations and document contract/quote/waybill/payment primary evidence with independent validation.
5. Keep baseline, scenarios and non-bankable hypotheses separated by flags.
6. Test negative cases and compare observed reality vs assumed demand; reconcile all repeated data grains.
7. Add immutable release note and versioned filenames, avoid rewriting old research.
8. CI should validate all public CSVs and source links; record current GitHub workflow outcome, no assumed success.
9. New institutional demands/port/rail results should become GitHub Issues with evidence acceptance criteria and exact source IDs.
10. Publish only verified claims; annotate engineering feasibility, legal permission, and financial bankability separately.

## Commercial pilot gate
Draft RFQ → send/record date → signed quote → waybills → actual gate/ETA data → paid invoices → 24-month group baseline → new/diverted/duplicate reconciliation → legal/capacity clearance → contractual commitment → investment gate review. None may be skipped by imputation.

## Safeguards
No secrets, nonpublic unredacted invoices or private buyer data in GitHub. A private repo is not a substitute for contractual permission and data minimization.
